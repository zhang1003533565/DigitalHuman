# 数字人持续直播功能设计

## 目标

在游客端新增独立数字人直播页。直播由后端统一时间轴持续运行，游客进入或退出不改变直播状态；所有游客在同一时间看到相同的直播文案进度。管理端负责维护、排序、启停和发布直播文案。

## 核心体验

- 地图页“进入直播间”按钮跳转到受保护路由 `/live`。
- 进入直播页后直接加入当前直播进度，不从第一条文案开始。
- 数字人按照已发布文案及每条播放时长循环讲解。
- 游客退出、刷新或重新进入不会停止、重置或重新开始直播。
- 游客文字或语音提问只中断当前游客的本地播报，不影响其他游客。
- 回答结束后重新同步直播状态，并从全局当前文案和当前进度继续。

## 方案选择

采用后端统一时间轴方案。

后端不为每个游客维护播放会话，也不依赖持续 SSE 连接推进文案。已发布版本保存统一 `publishedAt`，游客端使用服务器时间计算直播在循环时间轴中的位置。

未采用：

- SSE 持续广播：断线恢复、连接治理和服务重启恢复成本更高。
- 后台定时任务逐条推进：多实例一致性和调度误差处理更复杂。
- 纯前端时间推算：无法可靠解决游客本机时间偏差和统一发布状态。

## 时间轴模型

### 已发布版本

每次“立即发布”生成一个不可变直播版本：

- `versionId`：发布版本标识。
- `publishedAt`：服务器时间，以 UTC 时间戳返回。
- `totalDurationMs`：全部启用文案时长总和。
- `items`：发布时冻结的有序文案快照。

文案快照包含：

- `itemId`
- `title`
- `content`
- `durationMs`
- `sortOrder`

### 当前进度计算

游客端获取：

- `serverTime`
- `versionId`
- `publishedAt`
- `totalDurationMs`
- 有序文案快照

计算规则：

1. `elapsed = max(0, serverTime - publishedAt)`。
2. `cycleOffset = elapsed % totalDurationMs`。
3. 按文案时长累加定位当前文案。
4. 当前文案内进度为 `cycleOffset - 当前文案起始偏移`。
5. 客户端以 `serverTime - Date.now()` 保存时钟偏差，后续本地计时使用校准后的服务器时间。

文案循环结束后无缝回到第一条。发布新版本后，所有新同步请求使用新 `versionId` 和新时间轴。

## 后端设计

### 数据模型

新增直播文案草稿表，至少保存：

- 标题
- 文案正文
- 播放时长（毫秒）
- 排序值
- 启用状态
- 创建时间、更新时间

新增直播发布版本和版本条目快照。已发布版本不可被草稿编辑直接修改，避免正在直播的内容发生非原子变化。

### 游客接口

`GET /api/visitor/live/status`

返回当前已发布版本、服务器时间、完整有序文案快照和时间轴总时长。接口不创建游客播放会话。

无已发布版本或启用文案为空时，返回明确的 `notPublished` 状态，而不是伪造时间轴。

### 管理接口

- 查询直播文案草稿列表。
- 新增文案。
- 修改标题、正文、时长和启用状态。
- 删除未发布草稿文案。
- 批量调整排序。
- 立即发布当前启用文案。
- 查询当前已发布版本摘要。

发布操作在单个事务中完成：校验至少存在一条启用文案、每条时长合法、排序确定，然后创建版本及条目快照。发布完成时间由数据库/服务端统一生成。

### 权限

- 游客状态接口沿用游客端受保护访问规则。
- 文案维护与发布接口仅管理员可访问。
- 游客接口不返回草稿、禁用文案或管理审计字段。

## 游客端直播页

### 页面结构

- 复用 `VisitorTopNav` 和 `MobileBottomNav`。
- 主舞台复用现有 Live2D 模型、动作、口型和语音合成能力。
- 展示“直播中”状态、当前文案标题、字幕、当前条进度和下一条预告。
- 互动区域展示直播提示、游客问题和数字人回答。
- 支持文字输入、语音输入、发送、停止当前本地回答。

### 播放状态

页面维护以下本地状态：

- `syncing`：首次或恢复同步。
- `broadcasting`：跟随统一直播时间轴。
- `asking`：游客问题正在提交。
- `answering`：播放该游客专属回答。
- `resuming`：回答结束后重新同步时间轴。
- `unavailable`：没有已发布直播内容。

进入页面、浏览器重新获得可见性、回答结束和检测到版本变化时重新拉取状态。

### 本地语音与时间轴

- 当前文案只对当前游客合成/播放音频，后端统一的是文案时间轴，不是共享音频流。
- 加入直播时从当前文案的时间偏移开始。若语音引擎无法精确从音频中间开始，可从当前文案开始合成，同时 UI 仍显示全局进度；下一条起完全对齐。
- 游客提问时停止当前本地直播语音，播放回答。
- 回答完成后丢弃提问前的本地索引，重新请求直播状态，不重放被打断文案。
- 直播状态同步不得复用或污染普通 AI 导览页的会话历史。

### 路由入口

- 新增受保护路由 `/live`。
- 地图页直播卡主按钮跳转 `/live`。
- “语音互动”按钮继续跳转普通 AI 导览页，保持两种体验边界清晰。
- 直播页顶部提供返回地图入口。

## 管理端文案管理

新增“数字人直播”管理页面和侧边栏入口。

页面包含：

- 当前发布状态：版本、发布时间、启用条数、循环总时长。
- 草稿文案表格：标题、正文摘要、时长、排序、启用状态、更新时间。
- 新增和编辑表单。
- 启用/停用、删除和排序操作。
- “立即发布”主操作及发布确认。

排序采用明确数值或上下移动操作，发布时以后端最终排序为准。普通保存只更新草稿；只有立即发布才改变游客正在观看的直播。

## 错误与恢复

- 没有发布内容：直播页显示“直播内容准备中”，保留返回地图入口。
- 首次同步失败：显示重试按钮，不启动本地假直播。
- 播放中同步失败：继续使用最近一次有效版本和校准时钟，并显示轻量重连提示。
- 版本切换：停止旧版本本地语音，按新状态切换。
- 文案语音合成失败：字幕和进度继续，记录单条播放失败并在下一条重新尝试。
- 游客问答失败：保留问题并显示重试，随后允许恢复直播。
- 管理端发布校验失败：明确指出空文案、非法时长或无启用条目，不生成半成品版本。

## 响应式设计

- 桌面端：舞台为主区域，字幕与时间轴覆盖在舞台安全区，互动面板位于侧边。
- 移动端：舞台、字幕/进度、互动面板按纵向文档流排列。
- 固定底部导航继续预留安全区，输入和最后一条消息可滚动到导航上方。
- Live2D 画布可以限制手势，页面和互动区保持 `touch-action: pan-y`。
- 不新增移动端重复组件。

## 测试

### 后端

- 时间轴首条、条目边界、循环边界和多轮循环计算。
- 服务器时间早于发布时间的防御处理。
- 空发布状态。
- 发布快照不受后续草稿编辑影响。
- 发布事务校验、排序和权限。

### 游客端

- 服务器时钟偏差和当前文案计算。
- 中途加入不从第一条开始。
- 提问后重新同步并跳到全局当前进度。
- 版本变化切换。
- 地图按钮路由跳转与受保护路由。
- 加载、空状态、同步失败和语音失败。
- 移动端文档流、底部安全区与手势契约。

### 管理端

- 草稿增删改、启停、排序和发布交互。
- 发布确认、校验错误和已发布摘要。
- API 契约与侧边栏入口。

## 非目标

- 不实现真实视频推流、直播录制、回放或 CDN 分发。
- 不让游客控制全局直播暂停、切换或重置。
- 不在第一版实现点赞、礼物、关注、在线人数或公开弹幕广播。
- 不将游客专属问答广播给其他游客。

# 游客端统一导航设计

## 目标

将首页当前使用的导航视觉与交互提取为游客端唯一顶部导航组件，替换其他游客页面的旧导航样式，避免首页与功能页面出现两套导航。

## 组件设计

新组件命名为 `VisitorTopNav`，负责：

- 统一显示品牌“灵山智游”。
- 统一显示：首页、AI 导览、路线推荐、景点地图、游览贴士、反馈记录、会话历史。
- 根据当前路由显示激活菜单。
- 保留头像、用户身份、个人资料和退出登录菜单。
- 保留现有手机端隐藏顶部菜单、使用底部导航的响应式行为。

组件内部维护固定菜单配置。页面只传入 `onLogout`，不再允许页面单独修改标题、菜单或视觉变体。

## 替换范围

- 首页删除 `HOME_NAV_ITEMS`、`title`、`items` 和 `variant` 参数。
- 数字人、路线、地图、游览贴士、反馈、历史、个人资料、景点推荐和路线推荐列表全部改用 `VisitorTopNav`。
- 删除旧 `AppTopNav.tsx`、`AppTopNav.css` 及旧的 default/home 两套样式分支。
- 新组件沿用首页的紧凑高度、透明深色背景、金色激活下划线和首页头像样式。

## 兼容与边界

- 不修改页面路由。
- 不修改移动端 `MobileBottomNav`。
- 不修改登录页或管理后台导航。
- 页面容器仍负责自身内容布局，统一导航只负责顶部区域。
- 模块页原有绝对定位导航改为适配统一组件，但不覆盖页面内容。

## 验证

- 静态契约测试确认所有游客页面只引用 `VisitorTopNav`。
- 测试确认七个菜单路径与文字完整。
- 扫描确认不再存在 `AppTopNav`、`HOME_NAV_ITEMS`、`variant="home"` 或页面级菜单配置。
- 运行游客端 Lint、全部 Node 测试和生产构建。
- 检查桌面导航激活态及移动端底部导航没有回归。

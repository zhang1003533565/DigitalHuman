# 移动数字人直播评论流设计

## 背景

当前数字人页面在移动端沿用桌面聊天面板：角色设置、完整消息历史和输入区持续占据数字人下方的大块空间。虽然功能完整，但视觉重心落在聊天框而不是数字人，页面也更像客服会话，而不是沉浸式景区导览。

本次将移动端改为类似直播间的轻量互动结构：数字人舞台保持主视觉，最近问答以左下角评论流叠加在舞台上，输入与语音操作固定在底部导航上方。完整聊天历史和高级设置按需展开。桌面端布局保持不变。

## 目标

- 移动端首屏突出数字人，不再常驻完整聊天面板。
- 最近问答以直播评论流形式自然更新，并避免遮挡数字人面部。
- 游客可以在不离开舞台的情况下文字提问、语音提问和使用快捷问题。
- 现有会话、推荐卡片、语音合成、语音识别、数字人嘴型与模型切换能力继续复用。
- 完整历史和厂家、音色、模型设置仍然可达，但不占据默认首屏。
- 桌面端视觉和交互不改变。

## 信息架构

移动端 `.live2d-page` 采用一个舞台容器，内部从上到下分为四层：

1. 数字人画布与舞台背景。
2. 顶部轻量状态区。
3. 左下角直播评论流与快捷提问。
4. 底部固定互动栏。

固定底部导航仍由全局应用外壳负责。互动栏位于底部导航上方，并通过现有安全区变量计算位置，不重复创建页面级底部安全区。

## 默认舞台

- 数字人画布占据导航栏与互动栏之间的主要可视区域。
- 数字人保持居中，移动端优先保证头部、上半身和手部可见。
- 当前运行状态缩为舞台顶部的小型半透明标签，只展示状态点和简短文本。
- 右上角提供“设置”按钮，打开移动设置面板。
- 不渲染带边框的大型 `.digital-human-chat` 卡片外观。

## 直播评论流

### 展示

- 评论流固定在舞台左下区域、互动栏上方。
- 默认展示最近 5 条消息；新消息从底部进入，较旧消息向上移动并逐渐降低透明度。
- 消息使用内容宽度而非整行宽度，背景为轻量半透明圆角底，不形成大面积聊天面板。
- 游客消息显示“我”标识；数字人消息显示“灵灵”标识和品牌蓝色强调。
- 长文本最多显示 3 行，超出内容在默认评论流中截断；点击评论流可打开完整历史面板。
- 加载、语音识别和数字人思考状态作为短状态消息进入评论流，不单独占据大卡片。

### 更新与滚动

- 默认评论流不允许用户内部滚动，避免与页面纵向手势竞争。
- 新消息到达时更新最近 5 条，不调用会推动页面的 `scrollIntoView`。
- 完整历史面板内部保留有界纵向滚动，并加入移动局部滚动白名单契约。
- `prefers-reduced-motion` 下取消位移动画，只进行透明度切换。

### 推荐结果

- 数字人返回景点、路线或服务推荐时，默认评论流只显示摘要和“查看推荐”按钮。
- 点击“查看推荐”打开完整历史面板并定位到对应结果卡片。
- 不把大型推荐卡片直接叠加在数字人舞台上。

## 底部互动栏

- 互动栏固定在移动底部导航上方，使用单行半透明胶囊容器。
- 主输入占据剩余宽度，提示文字为“问问灵灵…”。
- 右侧提供语音按钮和发送按钮，触控目标不小于 44px。
- 键盘弹出时互动栏跟随可视视口，不能被软键盘遮挡。
- 输入框按 Enter 发送；Shift+Enter 保留换行，与现有桌面行为一致。
- 发送后保持舞台视图，不自动打开完整历史。

## 快捷提问

- 在评论流与互动栏之间展示一行可横向滑动的快捷问题：`景点讲解`、`路线推荐`、`附近服务`。
- 快捷问题使用真实提问文案调用现有 `sendQuestion`，不新增后端协议。
- 横向轨道明确使用 `overflow-x: auto` 与 `overflow-y: hidden`，不得成为纵向滚动容器。

## 完整历史面板

- 点击评论流或“查看全部”打开从底部升起的历史面板。
- 面板最大高度为可视区域的 72%，顶部包含标题、消息数量和关闭按钮。
- 内部复用现有消息气泡、结果卡片和建议操作。
- 面板关闭后焦点返回触发按钮；支持 Escape 关闭。
- 背景遮罩点击关闭，打开期间锁定面板外交互，但不销毁会话和语音状态。

## 移动设置面板

- 厂家、音色和模型选择从默认舞台移入单独的底部设置面板。
- 设置入口位于舞台右上角。
- 面板复用现有选项和选择处理函数，不改变会话存储、模型切换或播报状态逻辑。
- 切换完成后关闭对应选择菜单，并在顶部状态标签显示简短确认。
- 正在播报时沿用现有禁用逻辑。

## 状态与数据流

- `messages` 继续作为唯一会话消息源。
- 默认评论流通过 `messages.slice(-5)` 派生，不复制消息状态。
- 完整历史面板读取全部 `messages`。
- `draft`、`sendQuestion`、`handleSend`、语音识别、语音合成和流式回答逻辑保持不变。
- 新增的 UI 状态仅包括：完整历史面板开关、设置面板开关，以及推荐结果的目标消息定位。
- 桌面端继续渲染现有完整聊天面板；移动端通过响应式结构或样式显示直播评论体验。

## 无障碍

- 评论流使用 `aria-live="polite"`，但只宣布新增消息，避免重新朗读全部 5 条。
- 设置、完整历史、关闭、语音和发送控件具有明确中文可访问名称。
- 底部面板打开后将焦点移入面板，关闭后恢复触发按钮焦点。
- 颜色对比、触控尺寸和焦点样式沿用现有移动设计令牌。

## 错误处理

- 发送失败以数字人系统消息进入评论流，并允许在完整历史面板中查看完整错误。
- 数字人未就绪时禁用发送和语音入口，状态标签展示加载或失败原因。
- 语音识别失败继续使用现有错误状态，不清空用户已输入内容。
- 面板状态不得影响正在进行的流式回答或语音播放。

## 响应式边界

- `max-width: 768px` 使用直播评论流布局。
- 桌面端保留当前 `.digital-human-chat` 完整聊天布局。
- 移动页面根保持自然高度和外层单一滚动所有者契约。
- 评论流、快捷问题和互动栏不得创建页面级纵向滚动。
- 只有完整历史面板、设置选项列表等明确限高区域可独立纵向滚动。

## 测试策略

- 契约测试确认移动端渲染评论流、快捷问题、底部互动栏、设置入口和历史面板入口。
- 断言默认评论流最多读取最近 5 条，且不渲染完整消息列表。
- 断言桌面完整聊天面板仍然存在。
- 断言快捷问题调用现有 `sendQuestion`。
- 断言历史与设置面板具备打开、关闭、Escape 和焦点恢复行为。
- 响应式测试确认移动舞台没有常驻聊天卡片，互动栏位于底部导航上方。
- 滚动契约确认快捷问题横向滚动、评论流不纵向滚动、面板内部有界滚动。
- 运行全部游客端 Node 测试、ESLint、TypeScript 和 Vite 生产构建。

## 完成标准

- 移动首屏以数字人为绝对主视觉，不再出现常驻大型聊天框。
- 最近问答以左下角直播评论流展示，新消息清晰且不遮挡数字人面部。
- 文字、语音和三个快捷问题均可直接发起现有导览问答。
- 完整历史、推荐结果和厂家/音色/模型设置均可按需访问。
- 页面纵向滑动、局部面板滚动、软键盘和底部导航互不冲突。
- 桌面端无视觉和功能回归。
- 自动化验证全部通过。

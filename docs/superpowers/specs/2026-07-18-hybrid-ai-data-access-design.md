# 景点知识发布与旅游统计问答设计

## 目标

让景点正式资料和旅游行为统计安全地参与模型问答，同时保持来源可控、数据可追踪、统计不过期且不泄露游客明细。

采用混合架构：景点正式资料由管理员审核后发布到指定 MaxKB 知识库；旅游行为数据不进入向量库，由模型通过受控的脱敏聚合接口读取。游客端只能访问白名单统计指标，后台可访问更细的聚合分析，但任何模型均不得读取或输出单个游客明细。

## 产品边界

- `/admin/scenic-structured` 仍是景点资料导入暂存区；未匹配或未应用的记录不能发布到知识库。
- 只有已应用到正式景点的数据可以生成知识文档。
- 保存业务数据不会自动影响模型；管理员必须预览并点击发布。
- 管理员在发布时选择 MaxKB 账号和目标知识库。
- 景点资料修改后标记为待重新发布，不自动覆盖已发布知识。
- `/admin/travel-analytics` 不提供“导入知识库”，改为管理 AI 统计权限和验证统计问答。
- 游客端首期只开放热门景点、平均停留时长、平均消费、平均满意度和常见客群五类统计指标。
- 后台可以使用更多聚合维度，但不能获取单个游客记录。
- 首期不开放模型生成任意 SQL、任意字段组合或明细查询。

## 总体架构

新增独立的 AI 数据发布与统计查询边界，不把知识发布逻辑耦合进现有 DOCX/Excel 导入服务。

景点知识链路：

1. 管理员将结构化导入记录匹配并应用到正式景点。
2. 页面从正式景点、景点详情及允许公开的关联信息生成发布预览。
3. 管理员选择 MaxKB 账号和知识库并确认发布。
4. 后端生成稳定 Markdown 文档并通过 MaxKB OpenAPI 导入。
5. 发布记录保存目标、远端文档标识、内容摘要、版本和状态。
6. 游客景点问题继续通过指定 `knowledgeId` 走 MaxKB 检索。

旅游统计链路：

1. 聊天服务识别统计类问题并映射到固定指标枚举。
2. 统计服务在授权范围内读取 `travel_analytics_record`，完成解析、脱敏和聚合。
3. 游客端仅获得白名单指标、有效样本数、统计截至时间和必要的维度标签。
4. 模型依据结构化统计结果组织自然语言答案，不接触原始游客记录。

## 景点知识发布

### 发布来源

发布内容必须从正式景点及其正式详情读取。`scenic_spot_structured_record` 只用于定位已应用的正式景点，不作为最终文档来源。这样可以保证地图、游客端展示和模型回答使用同一份主数据。

知识文档至少包含：

- 景点业务编码、名称和位置；
- 建筑景观参数；
- 核心功能；
- 文化内涵；
- 详细介绍；
- 游玩亮点；
- 演艺或开放信息；
- 允许公开的游客须知和备注；
- 来源版本、生成时间和正式景点 ID。

空字段不输出。直播密钥、内部状态、音视频管理字段和其他非公开配置不得写入知识文档。

### 发布记录

新增景点知识发布记录，至少保存：

- 正式景点 ID；
- MaxKB 账号 ID；
- 目标知识库 ID 和展示名称快照；
- MaxKB 文档 ID；
- 逻辑文档键；
- 已发布内容摘要；
- 发布版本；
- `publishing`、`published`、`outdated`、`failed`、`withdrawn` 状态；
- 最近错误信息；
- 发布人、发布时间和更新时间。

逻辑文档键由正式景点 ID 稳定生成，用于幂等控制。内容摘要用于判断正式资料是否相对已发布版本发生变化。

### 创建、重发与撤回

- 首次发布创建 MaxKB 文档。
- 重新发布优先更新原文档。
- 若 MaxKB OpenAPI 不支持安全的整文档替换，则先创建并确认新文档可用，再删除旧文档并切换发布记录，避免失败时知识空窗。
- 同一景点和目标知识库同时只能有一个发布任务。
- 重复提交相同内容返回现有发布结果，不创建重复文档。
- 正式景点删除或下线不自动删除远端知识；管理员执行“撤回知识”后才移除问答范围。
- 撤回成功保留本地审计记录，状态变为 `withdrawn`。

### 页面交互

`/admin/scenic-structured`：

- 未匹配或未应用记录显示“请先应用到正式景点”，不展示发布操作。
- 已应用记录显示知识状态与“发布到知识库”。
- 发布抽屉提供 MaxKB 账号、目标知识库、生成文档预览和确认操作。
- 发布成功显示知识库名称、远端文档 ID、发布时间和发布版本。
- 正式资料修改后显示“内容已更新，待重新发布”。
- 失败状态展示经过脱敏的失败原因和重试入口。
- 已发布记录提供撤回操作，撤回前明确提示影响。

正式景点管理页也应展示同一发布状态，避免管理员只能回到导入暂存页确认知识是否最新。

## 旅游统计问答

### 权限分层

游客端只能调用以下固定指标：

- `popular_attractions`：热门景点；
- `average_stay_duration`：平均停留时长；
- `average_spend`：平均消费；
- `average_satisfaction`：平均满意度；
- `common_visitor_segments`：常见客群。

后台模型可以增加经审核的时间、景点类型、年龄段或性别等聚合维度，但接口仍只返回分组统计，不返回 `tourist_id`、昵称或任何原始行。

### 数据规范化

- 金额、时长、满意度、人数和日期字段在聚合前进行规范化解析。
- 无法解析的值不参与对应指标，并计入无效样本数。
- 每个指标返回总样本数、有效样本数、统计截至时间和口径标识。
- 细分结果默认至少需要 10 条有效记录；不足时返回“样本不足”，不输出细分值。
- 热门景点和常见客群默认只返回有限的前几项，避免模型获得可用于反推个体的长尾数据。

### 接口边界

游客统计接口使用枚举化指标和受控参数，不接受 SQL、字段名、排序表达式或任意过滤语句。服务端根据当前用户角色选择允许的指标和维度，不能依赖前端隐藏参数实现权限控制。

统计响应只包含：

- 指标名称和口径；
- 聚合值或排名；
- 有效样本数；
- 统计范围与截至时间；
- 样本不足或数据质量提示。

### 页面交互

`/admin/travel-analytics` 增加“AI 数据权限”区域：

- 启用或关闭游客端统计问答；
- 展示游客端允许的五项指标；
- 展示统计记录数、数据更新时间和解析质量摘要；
- 提供“测试模型回答”，验证每类白名单指标的实际输出；
- 明确提示游客 ID、昵称和单条记录不会提供给模型。

统计结果使用短时缓存。Excel 导入、记录新增、编辑或删除后立即使相关缓存失效，下一次问答重新计算。

## 聊天编排

聊天服务在模型生成最终答案前完成受控路由：

- 景点事实、历史文化、玩法和开放信息问题走 MaxKB 检索；
- 群体趋势和统计问题走旅游统计服务；
- 同时包含两类意图时可以合并两种来源；
- 请求超出白名单统计范围时明确拒绝明细分析，并给出可回答的统计范围；
- 统计答案必须包含统计截至时间；
- 知识库和统计来源均不足时不得编造结论。

游客端不得通过请求参数自行指定后台统计权限。后台与游客端使用不同的服务授权上下文。

## 异常与一致性

- MaxKB 不可用、账号禁用或知识库不存在时，发布失败并保留旧知识版本。
- 发布期间正式景点被修改时，本次结果标记为 `outdated`，不得显示为最新版本。
- MaxKB 错误信息在保存和展示前移除密钥、认证头和敏感地址参数。
- 发布失败不回滚已保存的正式景点资料。
- 统计字段解析失败时降级到有效样本，并明确数据质量；全部无效时不生成统计结论。
- 统计缓存失效失败时优先绕过缓存重新计算，不能继续返回已知过期结果。
- 被撤回的知识文档不能继续作为默认知识来源；撤回失败时保持当前发布状态并提示重试。

## 验证

### 后端

- 景点发布来源只读取正式景点与正式详情；
- 未匹配、未应用记录禁止发布；
- 首次发布、幂等重复发布、重新发布、安全切换和撤回；
- 发布过程中正式资料变化导致过期状态；
- MaxKB 失败保留旧版本且错误信息脱敏；
- 游客统计只支持白名单指标和参数；
- 游客 ID、昵称和原始记录不会出现在统计响应或模型上下文；
- 样本阈值、无效字段处理、有效样本数和统计截至时间；
- 数据变更后的缓存失效；
- 游客与后台统计权限隔离。

### 前端

- 未应用记录不提供发布按钮；
- MaxKB 账号与目标知识库选择、文档预览和确认发布；
- 发布中、已发布、待重新发布、失败和撤回状态；
- 失败重试和重复点击保护；
- AI 数据权限区域、五项指标说明、数据质量摘要和测试回答；
- Observer 角色只读且不能发布、撤回或修改 AI 权限。

### 集成验证

- 使用真实 MaxKB 验证文档创建、重新发布、安全替换、检索和撤回；
- 验证游客端景点知识问答能够命中新发布文档；
- 验证五类统计问题返回正确聚合结果、样本数和截至时间；
- 运行后端 Maven 测试、管理端契约测试、ESLint 和生产构建。

## 非目标

- 不把原始旅游行为 Excel 或数据库明细上传到 MaxKB。
- 不允许模型生成或执行任意 SQL。
- 不开放单个游客画像、消费明细或访问轨迹问答。
- 不自动发布景点资料。
- 不在首期实现跨多个知识库同时发布同一景点。

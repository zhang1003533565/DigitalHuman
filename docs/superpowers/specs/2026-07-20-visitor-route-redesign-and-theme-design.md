# 游客端路线推荐重设计与独立主题设计

## 目标

将路线推荐页从信息密集的分析面板重设计为面向游客的两段式决策页面，让用户先快速选出适合自己的路线，再查看地图和行程细节。同时为登录后的游客端增加独立于管理后台的“自动 / 日间 / 夜间”主题能力。

## 用户任务

页面按以下顺序帮助用户完成任务：

1. 根据兴趣、游玩时长和步行强度缩小选择范围。
2. 快速比较三条候选路线并选中一条。
3. 在地图和时间轴中理解路线顺序。
4. 按需查看沿途餐饮、卫生间和服务点。
5. 在景区地图中继续浏览或导航。

## 设计原则

- 用户语言优先，不展示算法和后台分析口吻。
- 先选择、后展开，避免在首屏同时呈现全部详情。
- 一个页面只保留一个主要纵向滚动边界。
- 日间与夜间主题都必须保持品牌一致性、清晰层级和足够对比度。
- 游客端与管理后台只复用设计思路，不共享主题状态或存储配置。

## 页面信息架构

### 1. 全局顶部导航

- 在游客头像左侧增加主题入口。
- 入口使用项目现有图标库中的主题图标，具有明确的无障碍名称。
- 点击后显示“自动 / 日间 / 夜间”三个选项，并标明当前状态。
- 桌面端入口常驻顶部导航；移动端入口放入游客菜单，避免挤压主导航。

### 2. 路线选择区

- 主标题使用“今天想怎么玩？”。
- 辅助文案说明用户可以先选偏好，再比较推荐路线。
- 兴趣、时长和步行强度改为轻量分组筛选按钮，不再使用纵向后台式表单。
- 筛选区之后展示最多三张路线卡。

每张路线卡只展示：

- 路线名称。
- 一句适合人群或游玩目标。
- 时长、距离和强度。
- 最多三个主要景点。
- “推荐”或“很适合你”等自然标签。
- “查看行程”主操作。

路线卡不展示精确匹配分数、排名算法、`Route Planner`、`Route Value` 或长段取舍分析。内部推荐分数仍可用于排序，但不直接暴露给游客。

### 3. 路线详情区

用户选中路线后，详情区在路线卡下方自然出现：

- 左侧约 60% 为地图，展示路线轨迹、节点序号和当前启用的服务设施。
- 右侧约 40% 为纵向行程时间轴，展示节点名称、建议停留时间和简短说明。
- 详情顶部仅保留路线名称、时长、距离、强度和一句旅行提醒。
- 详情底部提供“在景区地图中打开”主操作。

沿途服务不再占据独立滚动面板，而是作为地图上方的“餐饮 / 卫生间 / 服务点”筛选开关。切换设施不会改变当前路线或地图视野中的路线轨迹。

### 4. 响应式结构

- 桌面端：路线卡横向排列，详情使用地图与时间轴双栏。
- 平板端：路线卡允许两列，详情根据可用宽度转为上下结构。
- 移动端：筛选、路线卡、地图、时间轴依次排列；时间轴可折叠，但默认展开前几个节点。
- 页面交由应用内容区持有唯一主要纵向滚动，不创建路线列表、节点列表或服务列表的嵌套滚动条。

## 文案规则

### 删除或替换

- `78 分匹配` → `很适合你` 或 `推荐`。
- `推荐理由` → 直接陈述适合人群，例如“适合第一次来，核心景点一次看全”。
- `选择取舍` → 旅行提醒，例如“行程较长，建议穿舒适的鞋”。
- `必经节点` → 仅在确有决策价值时显示“建议停留”。
- 删除装饰性英文小标题。

### 保留

- 时长、距离、步行强度。
- 主要景点和节点顺序。
- 建议开始时间。
- 与安全、体力和开放时间直接相关的提醒。

## 游客端独立主题

### 模式

游客端主题固定为三种：

- `auto`：07:00（含）至 19:00（不含）使用日间主题，其余时间使用夜间主题。
- `light`：始终使用日间主题。
- `dark`：始终使用夜间主题。

默认模式为 `auto`。主题切换即时生效，不刷新页面，不改变登录状态、当前路由、筛选条件或地图选中状态。

### 独立状态边界

- 游客端使用独立存储键 `digital-human.visitor-theme-mode`。
- 管理后台继续使用 `digital-human.admin-theme-mode`。
- 游客端根节点使用 `data-visitor-theme="light|dark"` 与 `data-visitor-theme-mode="auto|light|dark"`。
- 游客端不得读取或写入 `data-admin-theme`、`data-admin-theme-mode` 或后台存储键。
- 管理后台不得读取或写入游客端主题状态。

### 技术结构

- `VisitorThemeProvider` 负责读取、校验、时间判断、定时刷新、持久化和根节点属性。
- `VisitorThemeSwitch` 只负责展示与更新模式，由全局游客导航复用。
- 游客端通用颜色、背景、边框、文本、遮罩、阴影和状态色收敛为语义化 CSS 变量。
- 页面专项样式只消费主题变量，不分别维护互相漂移的整套颜色值。
- 所有登录后游客路由都必须迁移到这些语义变量，不允许只给路线页增加孤立的浅色覆盖。
- 地图实例在最终主题变化时更新地图样式；地图切换失败不影响页面其余主题。

### 视觉语言

日间主题：

- 使用偏暖的浅灰背景、白色卡片、深蓝正文和克制的青蓝强调色。
- 阴影用于表达层级，不使用大面积发光边框。
- 地图、弹层和筛选控件保持明亮但不过曝。

夜间主题：

- 沿用深海蓝品牌背景，提高正文、次要文字和边框对比度。
- 减少透明面板叠加，主要内容使用稳定的深色表面。
- 地图使用适合夜间的样式，避免深色页面中出现刺眼的高亮地图。

## 交互状态

### 默认状态

- 路线数据返回后自动选中第一条推荐路线。
- 页面不自动滚动到详情区。
- 当前路线卡使用边框、轻底色和“已选择”状态表达，不依赖强烈渐变。

### 筛选

- 调整筛选后即时更新路线卡。
- 当前路线仍在结果中时保持选择。
- 当前路线不再符合筛选时选中新的第一条结果。
- 没有匹配路线时显示解释性空状态和“清除筛选”操作。

### 路线选择

- 点击整张路线卡或“查看行程”均可选中路线。
- 选择后更新地图轨迹、节点标记和时间轴。
- 重复选择当前路线不会销毁或重新创建地图实例。

### 地图与服务设施

- 地图成功加载后显示路线轨迹和节点序号。
- 服务设施开关只控制对应设施标记。
- 地图加载失败时仍展示完整时间轴，并提供“重新加载地图”。
- 错误文案面向游客，不暴露 SDK、配置键或接口细节。

### 可访问性与动效

- 筛选按钮、路线卡、主题切换和地图入口支持键盘操作。
- 选中态不只依赖颜色，并提供语义状态或可见文字。
- 所有交互目标满足项目现有触控尺寸约束。
- 焦点样式在日间和夜间均清晰可见。
- 尊重 `prefers-reduced-motion`，关闭非必要位移和过渡动画。

## 数据与组件边界

- 继续使用现有 `/api/user/scenic/routes/recommend` 数据源，不修改后台发布流程。
- 推荐排序逻辑可保留现有派生数据结构，但展示层只消费用户需要的摘要字段。
- 路线选择、筛选和地图覆盖物继续保持单向数据流。
- 主题状态放在全局游客壳，不放进路线页面，确保首页、AI 导览、路线推荐和景点地图行为一致。
- 本次允许拆分路线选择区、路线卡、详情时间轴和地图设施筛选等局部组件，但不引入新的状态管理库。

## 错误与兼容处理

- `localStorage` 不可用或值非法时回退到 `auto`，当前会话仍可切换主题。
- 自动模式定时器仅在提供者挂载期间运行并正确清理。
- 首次渲染应在浏览器绘制前应用最终主题，避免主题闪烁。
- 路线请求失败时保留筛选区并提供重试入口。
- 地图失败与路线数据失败分别处理，互不遮蔽。

## 验收标准

### 路线页

- 首屏可以不阅读长文就比较三条路线。
- 页面不再展示精确匹配分数和装饰性英文标题。
- 桌面端没有路线列表、节点列表或服务列表的嵌套滚动条。
- 选择路线后地图和时间轴同步更新。
- 空筛选结果可以一键恢复。
- 桌面、平板和 390 × 844 移动视口均无横向溢出。

### 主题

- 自动模式在 07:00、18:59 和 19:00 边界得到正确主题。
- 手动日间和夜间选择可持久化并覆盖自动判断。
- 游客端与后台存储键、根节点属性和运行状态完全独立。
- 所有登录后游客路由在日间和夜间均不存在明显的主题混搭或不可读控件。
- 首页、AI 导览、路线推荐和景点地图完成桌面日间、桌面夜间和移动端重点视觉检查。
- 地图样式随游客主题更新，失败时页面仍可使用。

### 验证

- 为主题解析、存储隔离和根节点属性增加契约测试。
- 为路线筛选、选择保持、空状态和展示文案增加测试。
- 保留并扩展地图异步初始化回归测试。
- 运行游客端 Node 测试、ESLint、TypeScript 检查和 Vite production build。
- 在浏览器中检查桌面日间、桌面夜间、缓存地图 SDK 导航和移动端布局。

## 非目标

- 不修改管理后台主题实现或其存储键。
- 不改变路线推荐接口和后台路线发布流程。
- 不新增推荐算法、AI 调用或知识库检索。
- 不新增依赖。
- 不重新设计游客端主导航的信息架构。
- 不重新设计登录页；游客主题入口和主题覆盖范围从登录后的全局游客壳开始。
- 不在本次范围内重做景区地图的搜索、定位和设施业务逻辑。

## 与既有设计的关系

本设计替代 `2026-07-17-route-recommendation-decision-design.md` 中“左侧规划面板 + 右侧分析详情面板”的展示结构。既有确定性推荐排序与地图降级能力继续保留，但精确分数、排序解释和长段取舍文案不再直接面向游客展示。

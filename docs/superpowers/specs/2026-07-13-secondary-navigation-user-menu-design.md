# 次级导航迁入用户下拉框设计

## 目标

将“游览贴士、反馈记录、会话历史”从顶部主导航迁入头像下拉框，减少顶部横向占用，让桌面端更简洁，并保证移动端在隐藏主导航时仍能访问这些功能。

## 范围

- 修改游客端共享组件 `VisitorTopNav` 及其样式和契约测试。
- 不修改页面路由、页面内容、底部移动导航或认证逻辑。
- 不新增第二套移动菜单；桌面端与移动端共用头像下拉框。

## 信息架构

顶部主导航固定保留四项：

1. 首页
2. AI 导览
3. 路线推荐
4. 景点地图

头像下拉框按以下顺序展示：

1. 个人资料
2. 游览贴士
3. 反馈记录
4. 会话历史
5. 分隔线
6. 退出登录

用户信息头部保持不变。退出登录继续使用危险操作样式，与普通导航项分组。

## 组件与数据流

`VisitorTopNav` 内部维护两个常量：主导航项和用户菜单中的次级导航项。次级导航项包含路由、文字和图标；点击后复用 React Router 的 `navigate` 跳转，并立即关闭下拉框。

组件继续读取 `location.pathname`。当当前路径与次级导航项路由相同时，该项增加激活类和 `aria-current="page"`，视觉上使用金色文字与轻量背景，使用户知道当前所在页面。

个人资料保留为下拉框第一个可聚焦操作，确保现有打开菜单后的焦点行为不变。Escape、点击外部、窗口尺寸变化、鼠标离开和退出登录的关闭逻辑保持不变。

## 响应式与可访问性

- 桌面端顶部减少为四项，避免中等宽度下横向拥挤。
- 768px 及以下继续隐藏顶部主导航，头像下拉框成为三个次级功能的入口。
- 每个下拉项保持至少 44px 高度，满足触控操作。
- 下拉框在小屏可视宽度内展示；文字不截断核心菜单名称。
- 菜单仍使用当前 `role="group"` 语义，不引入与现有键盘模型不一致的 ARIA menu 行为。

## 错误与边界处理

- 路由跳转不新增异步状态或错误分支，沿用 React Router 行为。
- 用户信息缺失时继续使用现有头像首字母回退，不影响菜单可用性。
- 当前页面是次级导航页面时，顶部四项均不误显示激活；下拉框对应项负责显示当前状态。

## 测试标准

- 契约测试断言主导航仅包含四项，且不再包含三个次级入口。
- 契约测试断言下拉框按约定顺序包含个人资料、三个次级入口和退出登录。
- 断言次级入口点击时关闭菜单并导航。
- 断言当前次级路由应用激活类和 `aria-current="page"`。
- 断言下拉项移动端触控高度不低于 44px。
- 运行游客端全部 Node 测试、ESLint、TypeScript 与 Vite 生产构建。

## 完成标准

- 顶部不再出现“游览贴士、反馈记录、会话历史”。
- 三个入口均可从头像下拉框访问，桌面端和移动端行为一致。
- 当前次级页面状态可识别。
- 个人资料、退出登录、菜单关闭和焦点恢复行为无回归。
- 游客端自动化验证全部通过。
